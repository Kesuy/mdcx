# MDCx 4.x 优化完成度

本文把 4.x 静态审计建议映射到可验证的代码状态。状态只使用“完成 / 部分完成 / 待处理”，避免把过渡层误报为最终架构。具体当前版本始终以 `mdcx/consts.py::LOCAL_VERSION` 为准，不在本文写死版本号。

## 安全与发布基础

| 项目 | 状态 | 当前实现与验收 |
|---|---|---|
| HTTPS 默认验证、自定义 CA | 完成 | 爬虫和 LLM 共用安全配置；关闭验证必须显式选择不安全模式。 |
| 移除 OpenSSL 1.1 DLL | 完成 | 仓库和冻结产物均不再携带旧 DLL；构建验收检查归档。 |
| pytest 接入 CI/Release | 完成 | CI 和发布构建均运行 pytest，发布构建依赖测试通过。 |
| 原子配置写入与备份恢复 | 完成 | 临时文件、flush/fsync、replace 和有效备份恢复集中在配置 I/O 层。 |
| 密钥和 Cookie 系统密钥库 | 完成 | 敏感字段优先保存到 keyring；JSON 不再作为首选秘密存储。 |
| 单一版本源与旧文档清理 | 完成 | `mdcx/consts.py` 驱动包元数据、构建和发布。 |
| Windows 冻结启动可靠性 | 完成 | 构建过滤冲突 ICU，真实启动 `--smoke-test`；测试 FFmpeg 不进入 EXE。 |
| Windows EXE 详细信息同步 | 完成 | PE 文件说明、产品名、文件/产品版本、版权和语言由唯一版本源自动生成，并在构建后反向校验。 |
| GitHub Actions Node 24 | 完成 | Checkout/Python/uv/stale 均使用 Node 24 兼容版本；发布上传使用 GitHub CLI。 |

## 控制器与后台任务

| 项目 | 状态 | 当前实现与验收 |
|---|---|---|
| Qt TaskManager 与显式 shutdown | 完成 | 主窗口后台入口统一调度，退出时取消任务并关闭后台执行器。 |
| 清理主窗口裸 `threading.Thread` | 完成 | 主窗口不再创建临时线程；现有刮削工作线程仅保留协作式停止与有界等待。 |
| 主窗口职责拆分 | 完成 | 主窗口保留初始化、跨控制器路由和 Designer 兼容薄槽；页面行为进入独立控制器 / mixin。 |
| 配置声明式绑定 | 完成 | schema 覆盖普通控件、枚举、字段规则及主要复合集合；网站优先级保留专用绑定。 |

以上状态描述的是架构能力，不是要求每次低风险修改都执行完整回归。开发时按 `AGENTS.md` 的风险分级验证；共享核心、构建和发布路径再扩大测试范围，正式发布仍由 CI / Release workflow 执行完整质量门。
